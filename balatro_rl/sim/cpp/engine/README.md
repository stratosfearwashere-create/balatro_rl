# The C++ engine

`balatro_rl.sim._engine` is the whole game and its RL environment in C++. It is a port of the Python
simulator, not a new one: given the same seed and the same actions it reaches the same states, draws the
same random numbers and produces the same observation arrays and rewards.

| File | Ports | Contents |
|---|---|---|
| `tables_gen.hpp` | `jokers.py`, `items.py` tables | Generated by `tools/gen_engine_tables.py`. Never edit by hand. |
| `game.hpp` | `game.py`, `scoring.py`, `jokers.py`, `hands.py`, `cards.py` | `Game`: rules, scoring, the 150 jokers' hooks, shop, packs, consumables, bosses |
| `env.hpp` | `env.py`, `vec_env.py` | `Env`: action layout, candidates, legal mask, features, rewards. `VecEnv`: a thread pool over many `Env`s |
| `module.cpp` | | pybind11 bindings: `Game`, `Env`, `VecEnv` |
| `../pyrandom.hpp` | CPython's `random.Random` | Mersenne Twister and the exact `random`, `randrange`, `choice`, `shuffle`, `sample`, `choices` |

## Build

```bash
python setup_cython.py build
```

Only the engine:

```bash
python setup_cython.py build --only balatro_rl/sim/cpp/engine/module.cpp
```

On Windows the build cannot replace `_engine.pyd` while a Python process has it loaded.

## Use

```python
from balatro_rl.engine_env import CppEnv, CppVecEnv

env = CppEnv("RED", "WHITE")
obs = env.reset(seed=1)
obs, reward, done, info = env.step(action)

venv = CppVecEnv(512, "RED", "WHITE", seed0=7, threads=8)
obs = venv.obs                 # dict of [n, ...] arrays: live views, overwritten by the next step
rew, done, infos = venv.step(actions)
```

PPO on the engine:

```bash
python -m balatro_rl.train ppo --engine cpp --stake WHITE --envs 512 --steps 32 --batch 2048 --out checkpoints/ppo_cpp.pt
```

## How it stays the same as the Python game

The Python game is the specification. `tests/engine_diff.py` plays seeded games on both with the same
actions and compares, after every step:

- every field of the game, every card of every pile and the relative order of card ids;
- jokers and their state, the shop, the open pack, consumables, tags, flags;
- the state of the random generator, so the two draw the same numbers in the same order;
- with `--obs`: the nine observation arrays cell for cell, and the reward.

```bash
python -m pytest tests/test_engine.py -q
python -m tests.engine_diff --games 2000 --spice --obs --deep 12 --p-spice 0.3 --coverage
```

`--spice` injects random jokers, consumables, vouchers, bosses, tags and card changes into both games.
`--deep N` starts every hand at level N so play reaches the late antes. `--coverage` lists any joker,
consumable, boss, tag, voucher, pack, deck or stake the run never exercised.

## Changing the game

1. Change the Python game first. It remains the reference.
2. If a table changed (a joker's cost, a new voucher), run `python tools/gen_engine_tables.py`.
3. Port the change to `game.hpp` (or `env.hpp` for features).
4. Rebuild and run the differential test with `--spice --obs --coverage`.

## Representation

Keys are enums. Cards live in an arena and piles hold their ids; a card's id is its uid, and only the
order of uids matters (hand sorting). A joker's state dict is a small struct with "present" markers
(`val`, `rank`, `suit`, `hand`, `left`). Sets are bitmasks. Money is an integer; chips and targets are
doubles, so scores are exact below 2^53, as in the compiled scorer.

## Not ported

- `shape_phi` (the build potential is Python code), the strategic environment and the joker-pool
  restriction of the trainer. `Game` itself supports a joker pool.
- The search agent (`az/`), the round solver and the shop pricer still run on the Python game.
